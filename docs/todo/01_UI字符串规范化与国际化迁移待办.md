# 待办任务 01：UI 字符串资源规范化与多语言（i18n）迁移计划

> **序号**：01  
> **优先级**：低（技术债务 / 空闲时间逐步重构）  
> **创建时间**：2026-10-23  
> **核心目标**：彻底解决 Jetpack Compose 界面代码（`.kt`）中中文硬编码与 `strings.xml` 资源混用的问题，统一文案资产管理，并为日后支持日文、英文等多语言国际化奠定基础。

---

## 一、现状与问题分析

1. **混用现状**：
   - 部分文案（如 `label_completion_rate`、`btn_continue_learning`）定义在 `res/values/strings.xml` 中；
   - 另有相当一部分文案（如 `HomeScreen.kt` 中的 `Text("暂无复习项目")`、`Text("复习进度")`、`Text("今日新学进度")`）直接以中文硬编码在 Kotlin 文件中。
2. **潜在风险**：
   - 无法方便地支持出海或多语言界面切换（如日语原生界面、英文界面）；
   - 文案散落，产品或设计调整用词时难以全局排查和统一修改；
   - 代码可维护性与测试断言一致性较低。

---

## 二、字符串资源命名规范

为了保证整个项目各模块的 `strings.xml` 命名清晰且不冲突，推荐遵循以下规则：

### 命名格式：`[模块]_[页面/组件]_[类型]_[描述]`

| 类型代码 | 对应控件 / 场景 | 示例 |
| :--- | :--- | :--- |
| `title_` | 页面标题、卡片大标题 | `home_bento_learn_title` |
| `label_` | 标签、辅助说明文本、状态描述 | `home_bento_review_progress_label` |
| `btn_` | 按钮点击文案 | `home_btn_continue_learning` |
| `dialog_` | 弹窗标题、正文、提示 | `dialog_confirm_exit_content` |
| `format_` | 含有格式化占位符的文案 | `format_daily_goal_hint`（例如：`目标 %1$d 个`） |
| `empty_` | 列表或卡片空状态文案 | `home_review_empty_tip`（例如：`暂无复习项目`） |

## 四、开发避坑与最佳实践

1. **动态参数必须使用位置编号**：
   - 避免直接写 `%d`，统一规范写成 `%1$d`、`%1$s`，以便后续多语言翻译调整语序时不会导致崩溃。
2. **避免字符串拼接**：
   - 不要将半句话硬编码后在 Kotlin 里做 `+` 拼接；整句应当作为带占位符的完整资源放入 XML。
3. **保持模块内聚**：
   - 模块私有的文案放在对应模块自身的 `src/main/res/values/strings.xml` 中；
   - 跨模块通用的基础文案放入 `core:ui` 或 `core:designsystem` 的资源中。
