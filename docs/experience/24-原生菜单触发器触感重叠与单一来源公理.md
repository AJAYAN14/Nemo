# 原生菜单触发器触感重叠与单一来源公理

> 本文档记录全工程顶栏操作菜单接入原生液态菜单引擎后，因业务层按钮与底层视图重复触发触感振动导致振感厚重发钝的问题剖析、规整方案与单一来源原则。

---

## 一、 四列核心经验对照表

| 坑是什么（Problem & Root Cause） | 怎么避（Resolution & Practice） | 相关工具 / 文件 | 统一原则（Principle） |
| :--- | :--- | :--- | :--- | :--- |
| **坑 1：底层引擎与上层回调重复触发触感反馈造成振动波形叠加**<br>全工程顶栏悬浮菜单已统一接入原生 `NemoGlassMenuView` 引擎。底层在调用 `.open()` 时内部自带了一次标准的 `performHapticFeedback(HapticFeedbackConstants.TEXT_HANDLE_MOVE)`。而学习界面顶栏在 `onOpenChange` 回调中又显式调用了一次 `haptic.performHapticFeedback(...)`，导致手机线性马达在极短时间内连续收到两记脉冲信号，叠加后产生更重、发钝且带拖尾的“双击”手感，与错题界面的清脆单触感不一致。 | **触觉反馈统一收敛至底层单一来源**：<br>1. 坚决贯彻触感反馈单一来源原则，凡接入 `NemoNativeLiquidMenuTrigger` 的触发按钮，一律由底层原生引擎全权负责展开/长按/选择时的触感震动；<br>2. 彻底移除业务层 `onOpenChange` 回调中的任何手动触觉调用，保持各业务界面（错题、词库、测试、学习）交互手感 100% 纯粹与一致。 | `NemoGlassMenuView.kt`<br>`LearnHeaderMoreMenu.kt`<br>`CollectionActionMenu.kt`<br>`performHapticFeedback` | **触感反馈单一来源公理**<br>原生视图引擎已封装的标准触感反馈，上层业务回调严禁二次叠加；全工程同一交互组件的振动手感必须在物理层保持绝对一致。 |

## 二、 落地规范与关键代码对比

```kotlin
// 🔴 错误做法：在 onOpenChange 展开回调中二次手动注入震动，引发双重震动干涉
NemoNativeLiquidMenuTrigger(
    items = items,
    onOpenChange = { open ->
        ActiveNativeLearnMenuOpenState.value = open
        if (open) {
            haptic.performHapticFeedback(HapticFeedbackType.TextHandleMove) // 错误：与底层原生 open() 内部震动重复
        }
        if (open != isExpanded) {
            onClick()
        }
    }
)

// 🟢 正确规范：完全由底层原生引擎统一派发触觉反馈，上层保持纯净状态联动
NemoNativeLiquidMenuTrigger(
    items = items,
    onOpenChange = { open ->
        ActiveNativeLearnMenuOpenState.value = open
        if (open != isExpanded) {
            onClick()
        }
    }
)
```
