### 2.2 双轨单容器计算属性标准范式

```kotlin
// 1. 提取当前外观设置
val iconStyle = LocalSettingIconStyle.current
val isSoftTranslucent = (iconStyle == SettingIconStyle.MD3)

// 2. 声明式计算单容器属性（同色源、同尺寸）
val containerBgColor = if (isSoftTranslucent) color.copy(alpha = 0.15f) else color
val iconTint = if (isSoftTranslucent) color else Color.White

// 3. 单 Box + 单 Icon 稳定渲染（切换无跳变）
Box(
    modifier = Modifier
        .size(36.dp)
        .background(containerBgColor, RoundedRectangle(10.dp)),
    contentAlignment = Alignment.Center
) {
    Icon(
        imageVector = icon,
        contentDescription = null,
        tint = iconTint,
        modifier = Modifier.size(24.dp)
    )
}
```

## 3. 经验总结与后续开发准则
1. **防范一刀切陷阱**：在面对不同功能界面（如主设置列表 vs 紧凑仪表盘卡片）时，必须识别场景的信息密度。设置列表使用 42dp，仪表盘卡片使用 36dp，两者分别搭配 28dp 和 24dp 图标，保持完美的 2:3 黄金比例。
2. **纯净代码纪律**：严禁在源代码中添加元注释、口水套话或“搬运自原工程”等防守型说明；所有技术意图应通过清晰的变量命名与架构契约自然表达。
