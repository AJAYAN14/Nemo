# 33-原生液态菜单静止态本地化与转场防穿透避坑指南

> 记录 Nemo 项目中解决全工程顶栏原生液态菜单（`NemoNativeLiquidMenuTrigger`）在页面 Navigation 平移转场时跨越 Compose 图层层级、在屏幕中悬停漂浮残留的核心避坑与重构经验。

---

## 避坑复盘对照表

| 坑是什么 | 怎么避 | 相关工具 / 文件 | 统一原则 |
| :--- | :--- | :--- | :--- |
| **未展开静止态按钮强制由 DecorView 顶层 Overlay 托管绘制导致跨图层穿透悬浮残留**：`NemoGlassMenuView` 在未展开时将 `overlayDrawsChildren` 设为 true 掏空本地绘制，而全局 `GlassMenuOverlay` 直接挂载在 Window 的 DecorView 顶层。当 Compose 执行页面平移转场时，新页面无法遮挡比 ComposeView 更高层级的 Overlay，旧页面的 Menu 按钮随绝对坐标移动到屏幕正中间悬停漂浮，直到转场结束才突兀消失。 | **静止态本地化，展开态顶层化公理**：<br>1. 仅在真正激活或展开会话时（`menuActive == true` 或属于活跃会话），才交由顶层 Overlay 接管；<br>2. 静止态（`menuActive == false`）彻底回归本级 `NemoGlassMenuView` 自绘制微透胶囊底座与内容图标，天然遵循所属页面的平移变换、边界裁剪与 Compose Z 轴层级遮挡；<br>3. `GlassMenuOverlay` 在 `session == null` 时完全静默，彻底消除静止状态下的全屏无差别 DecorView 录制开销。 | `NemoGlassMenuView.kt`<br>`GlassMenuOverlay.kt`<br>`NemoLiquidMenu.kt` | **渲染宿主层级与生命周期严格对齐公理**：<br>控件在静止状态下的渲染层级必须严格依附于其逻辑所属的页面容器，严禁常驻挂载于全局 Window 顶层，杜绝任何跨图层穿透与转场悬浮残影。 |

---

## 架构演进与治理全景

```
【重构前：静止态全局托管（存在穿透与残影）】
Window DecorView
 └── ComposeView
 │     └── 旧页面（我的错题，转场平移中）
 │           └── AndroidView -> NemoGlassMenuView (放弃本地绘制 ❌)
 └── GlassMenuOverlay (覆盖全屏幕最顶层 ❌)
       └── 遍历 anchors 绘制 drawRestingAnchor (越过新页面文字，悬停在半空 ❌)

─────────────────────────────────────────────────────────────

【重构后：静止态本地化，展开态顶层化】
Window DecorView
 └── ComposeView
 │     ├── 新页面（滑入，层级最高，100% 遮挡旧页面元素 ✅）
 │     └── 旧页面（滑出，随 Compose 容器正常平移与边缘裁剪 ✅）
 │           └── AndroidView -> NemoGlassMenuView
 │                 ├── 静止状态：本地自绘制微透底座与图标，完全受页面容器管辖 ✅
 │                 └── 零顶层干扰：转场期间绝不发生 DecorView 越级悬浮 ✅
 └── GlassMenuOverlay (仅在 Active / 展开菜单会话时唤醒顶层弹出层 ✅)
```
