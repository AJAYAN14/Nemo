# 排序题调色盘收拢与假名入槽自发光及题干卡片重构避坑指南

> 本文档总结 Nemo 排序题界面重构中，彻底拔除历史孤岛色板（`SortingPalette`）与十年前发灰渐变、收拢至 `docs/design/color-palette` 原生 `SystemColors` 体系、保留假名微倾斜与弹簧动效、构建题干微卡片的避坑经验。

---

## 1. 核心技术问题与背景

1. **历史孤立调色板与发灰渐变（十年前陈旧感）**：
   原有 `SortingScreen.kt` 使用了硬编码孤立对象 `SortingPalette`（含 `BackgroundGradientLight`、`ContainerBgLight`、`MacaronColors`）。背景使用了发蓝发紫的垂直渐变，答题框带有蓝紫脏底色（`0xFFE0E7FF`），导致整体界面在现代 OLED / 高分屏上显得发灰发脏，完全脱节于 `docs/design/color-palette` 规范。
2. **彩色全屏泛滥缺乏高光对比**：
   原有假名字块在候选池未选状态即被赋予高饱和马卡龙色（粉红、亮黄、青绿混杂），导致屏幕缺乏层级秩序感。
3. **幽灵死代码（未支持的语法判断）**：
   源码中残留 `val isGrammarQuestion = questionAtTarget.word.level.startsWith("Grammar:")` 分支。而底层题库生成核心 `TestQuestionFactory.createSorting` 纯粹只支持单词假名拼写，该分支为恒假死代码。
4. **裸文本单薄与断层感**：
   顶部中文大字原先为孤立悬浮的裸文本，上方空荡且与下方答题框产生视觉断层。

---

## 2. 解决方案与实施策略

1. **底盘回归纯净系统色**：
   彻底移除廉价垂直渐变与 `SortingPalette`，画布底色收拢至 `MaterialTheme.colorScheme.background`（浅色柔和微暖浅灰，深色纯黑）；答题框使用纯白底色（`Color.White`，深色 `surfaceVariant.copy(alpha = 0.45f)`）配 1dp 微光细描边与 G2 连续圆角 `RoundedRectangle(24.dp)`。
2. **入槽点亮为 SystemColors 纯正系统色**：
   候选池中的字块保持纯白质感卡片与黑色加粗文字，克制纯净；选入答题框后通过 `getSystemAccentColor` 点亮为 `SystemColors`（系统蓝、靛蓝、薄荷绿、紫、橙、青蓝），深色模式自发光明度补偿，白字高对比度加粗。
3. **100% 完整保留假名入槽微倾斜动效**：
   保留 `val rotation = remember(char.id) { ((-8..8).random()).toFloat() }` 与 Spring 阻尼弹簧动效，维持磁吸积木般的物理灵动感。
4. **构建题干独立微卡片**：
   使用 G2 圆角 `RoundedRectangle(20.dp)` 打造题干微卡片，顶部放置 `假名排序` 题型微胶囊，中轴加固中文释义大字与辅助说明，消除裸文本单薄感。
5. **彻底根治幽灵语法代码**：
   拔除 `isGrammarQuestion` 判断与相关冗余分支，文案收归为纯正的 `test_sorting_tag_word` 与 `test_sorting_instruction_word`。
