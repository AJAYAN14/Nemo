# 原生液态菜单长短按双轨分发与功能开关时长微调避坑指南

> 本文档总结 Nemo 学习界面液态玻璃菜单在处理“功能布尔开关”与“数值时长微调”双重意图时的交互设计冲突与技术避坑经验。

---

## 核心避坑对照表

| 坑是什么 | 怎么避 | 相关工具 / 文件 | 统一原则 |
| :--- | :--- | :--- | :--- |
| **单条目双重意图冲突**：菜单项同时需要控制功能开启/关闭与参数配置（如自动翻面 5s、答案等待 1s），直接点击弹窗会彻底剥夺用户随手开启或关闭的核心入口，导致功能无法关闭。 | **长短按双轨分发**：轻触单点（Click）专用作最快捷的【开启/关闭】切换（`keepOpen = true`，勾号 `✔` 与副标题即点即变）；长按（Long Press）专用于呼出高阶数值调节弹窗（`DurationPickerDialog`）。 | `LearnHeaderMoreMenu.kt`<br>`LearningScreen.kt` | **长短按双轨解耦公理**：高频二态操作走单点，低频参数配置走长按，杜绝弹窗打断主心流。 |
| **原生液态菜单缺少长按检测**：底层自定义 Overlay 仅支持 `ACTION_UP` 单击分发，若直接添加手势监听器易与 Jelly 流体拖拽及弹性滚动产生手势竞争与误触。 | **系统标准长按与滑动容差检测**：在 `ACTION_DOWN` 植入 `ViewConfiguration.getLongPressTimeout()` 延迟任务，位移超过 8dp 或触发滚动时立即撤回；命中时派发系统级 `HapticFeedbackConstants.LONG_PRESS` 振动并拦截随后的 UP 判定。 | `GlassMenuSession.kt`<br>`NemoGlassMenuView.kt`<br>`NemoLiquidMenu.kt` | **系统级规范手势与零竞争公理**：长按判定严格遵循系统推荐超时阈值与移动容差，触觉反馈必须在长按瞬间触发。 |
| **数值配置与状态脱节**：用户在弹窗中调整并确认新时长后，若底层开关仍处于此前关闭状态，会导致功能依然不生效，产生“设置失效”的负面体验。 | **参数配置联动激活**：用户在时长弹窗中点击“确定”提交新数值时，无论之前是否处于关闭状态，均联动将开关置为启用（`Toggle*(true)`）。 | `LearningScreen.kt`<br>`LearningEvent.kt` | **参数调节联动激活原则**：显式配置参数即代表用户启用该功能的明确意图，状态层必须主动联动。 |

---

## 最佳实践与架构图解

```
用户触摸菜单条目
   │
   ├─► 轻触点击 (UP) ────► 立即切换布尔开关 (Toggle) ──► 菜单保持展开，勾号 ✔ 实时亮起/熄灭，副标题变“当前: 1.0s / 已关闭”
   │
   └─► 长按 (LongPress) ─► 触发 LONG_PRESS 震动 ──────► 收起菜单并弹出刻度尺弹窗 ──► 确认后保存秒数并自动置为开启 (true)
```
