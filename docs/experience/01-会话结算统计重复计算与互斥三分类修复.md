# 会话结算统计重复计算与互斥三分类修复复盘

> 本文档记录学习会话（微会话）结算战报大屏中，复习卡片点击“重来”导致总词数虚增（如 10 词变为 11 词）的根因定位、修复方案与技术经验沉淀。

---

## 一、 问题现象与用户反馈

### 1. 现象描述
用户设定学习计划为 **10 词为一组**（微会话），在学习过程中：
- 4 个新词顺利学习；
- 6 个复习旧词中，有 1 个词点击了一次“重来”（遗忘/打入重学队列），随后在队列末尾重新攻克并通过；
- 最终 10 个单词全部学完，进入结算战报大屏时：
  - **顶部大标题赫然显示为：11 词**（而非实际设定的 10 词）；
  - **今日词量分类卡片**：
    - 旧词巩固：6 词（55%）
    - 新词拓展：4 词（36%）
    - 攻克：1 词（9%）
    - 三项相加：`6 + 4 + 1 = 11 词 (100%)`；
  - **顶部副标题平均用时**：以总时长除以 11，导致单词平均耗时被摊薄稀释。

### 2. 核心冲突与认知违和
- **用户心智**：“我明明只背了 10 个独立单词，为什么结算页面凭空捏造出第 11 个词？”
- **语义混淆**：“词”（独立词汇掌握量）与“次”（卡片做题交互次数）混为一谈。如果多点几次重来，词数会继续虚增，甚至使日目标完成进度失真。

---

## 二、 底层根因分析（Root Cause Analysis）

通过代码溯源，该问题是由底层统计语义与 UI 累加逻辑的脱节造成的：

1. **底层数据库统计语义（去重独立词）**：
   - `wordRepository.getTodayReviewedWords(today)` 查询的是今日产生复习行为的**独立单词列表**，其结果已经包含了那个点了“重来”但今天完成了复习的旧词，因此 `sessionReviewCount = 6`。
2. **重学攻克计数（属性标记）**：
   - 当旧词评分 `< 3` 时，其 ID 被收录至 `relearnWordIds` 集合中，`sessionRelearnCount = relearnWordIds.size = 1`。
   - **在业务本质上，“攻克/重学”是“旧词复习”的一个属性子集，而非独立于旧词之外的第三种平行词汇。**
3. **UI 结算层的粗暴累加（Bug 爆发点）**：
   在 `LearningFinishedContent.kt` 历史代码中：
   ```kotlin
   // 历史错误逻辑：直接将子集与全集累加，产生一词两算（Double Counting）
   val sessionTotalCount = (sessionNewCount + sessionReviewCount + sessionRelearnCount).coerceAtLeast(1)
   // 4 (新词) + 6 (旧词全集) + 1 (重学子集) = 11 词！
   ```
   那个点了“重来”的旧词，既被算进了 6 个“旧词巩固”里，又被单列作为 1 个“攻克”叠加进去，导致数据重复计算。

## 三、 修复方案落地（方案 A：互斥三分类体系）

为了兼顾“独立总词数绝对真实”与“攻克难词的成就感高亮”，采用**互斥三分类**模型进行彻底重构：

### 1. 数学模型与定义
将原本存在交集的分类重构为完全互斥的三个区间：
- **新词拓展（New）**：$N = sessionNewCount$
- **攻克难词（Relearn / Lapse）**：$R = sessionRelearnCount$（经历波折重学并攻克的旧词）
- **顺畅巩固（Smooth Review）**：$S = \max(0, sessionReviewCount - sessionRelearnCount)$（一次性顺利通过的旧词）
- **微会话独立完成总词数**：
  $$Total = N + \max(sessionReviewCount, sessionRelearnCount)$$

在上述用户案例中：
- 顺畅巩固 $S = 6 - 1 = 5$ 词（50%）
- 新词拓展 $N = 4$ 词（40%）
- 反复攻克 $R = 1$ 词（10%）
- **独立总词数 $Total = 5 + 4 + 1 = 10$ 词（100%）！**

### 2. 涉及代码修改清单

#### ① 领域模型单一数据源：[LearningUiState.kt](file:///c:/Users/AJIAN14/WorkBuddy/Worktrees/Nemo/main-4a07b69b/feature/learning/src/main/java/com/jian/nemo/feature/learning/presentation/LearningUiState.kt)
在 `LearningUiState` 增加计算属性，确保业务逻辑收敛：
```kotlin
/** 本组微会话独立完成的单词/语法总数（新学 + 复习，攻克属于复习子集，杜绝重复计算） */
val sessionTotalCount: Int
    get() = (sessionNewCount + maxOf(sessionReviewCount, sessionRelearnCount)).coerceAtLeast(1)

/** 顺畅巩固复习数（一次性通过、未触发重学攻克） */
val smoothReviewCount: Int
    get() = (sessionReviewCount - sessionRelearnCount).coerceAtLeast(0)
```

#### ② 表现层渲染修复：[LearningFinishedContent.kt](file:///c:/Users/AJIAN14/WorkBuddy/Worktrees/Nemo/main-4a07b69b/feature/learning/src/main/java/com/jian/nemo/feature/learning/presentation/components/common/LearningFinishedContent.kt)
- 顶部大数字与海报分享弹窗统一绑定真实的 `sessionTotalCount`（显示为 **10 词**）；
- 三色圆角渐变进度条按 `smoothReviewCount` (绿)、`sessionNewCount` (蓝)、`relearnCount` (金) 瓜分比例；
- 下方第一栏“旧词巩固”展示真实顺畅复习数 `smoothReviewCount`，百分比为 `(smoothReviewCount / sessionTotalCount) * 100`；
- 第三栏“攻克”展示 `relearnCount`，三栏百分比加和严格等于 100%。

#### ③ 自动化防回归单测：[LearningUiStateTest.kt](file:///c:/Users/AJIAN14/WorkBuddy/Worktrees/Nemo/main-4a07b69b/feature/learning/src/test/java/com/jian/nemo/feature/learning/presentation/LearningUiStateTest.kt)
新增 `sessionTotalCount should not double count relearned review words` 与 `sessionTotalCount edge cases check` 单元测试，覆盖纯新词、纯顺畅复习、全攻克与混合模式，全部自动化通过。
