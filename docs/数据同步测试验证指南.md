# 数据同步（导出/导入）功能测试指南

本文档旨在为您或者测试人员提供一份详尽的操作手册，用于验证我们近期对“数据导入导出模块”所做的**极致瘦身**与**防串线加固**重构是否完全达到预期。

---

## 核心测试目标

1. **瘦身验证**：导出文件中绝不包含冗余的字典文本（如日文、假名、中文意思）。
2. **安全配置同步**：学习策略会被成功转移，但高风险的敏感信息（如 API Key）和强设备相关设置（如 TTS 发音引擎、UI 主题）绝对不会被打包导出，更不会在导入时覆盖目标手机的设定。
3. **精准的 rawId 防串线**：进度只会凭 `rawId` 精准对号入座，自增数字 ID 即使不一样也能找到对的词；本地找不到 `rawId` 对应词条的进度会被安全抛弃，绝不引发张冠李戴的乱入。

---

## 准备工作

- **两台测试环境**：可以使用两台手机（设备 A 与 设备 B），或者同一台手机（导出后清空 App 数据重装，扮演设备 B）。
- **工具**：电脑上的任意文本编辑器（用于查看备份 JSON 结构）。

---

## 🧪 测试用例 1：备份文件结构瘦身与白名单验证

### 操作步骤
1. 在 **设备 A** 上，前往设置，填写一些具有辨识度的数据：
   - 将“大模型 API Key”随便填一串密码（如 `sk-test-123456`）。
   - 将“主题”修改为深色模式。
   - 将“每日目标”修改为一个奇特的数字（如 `67`）。
2. 在应用中背诵几个单词和语法，故意做错几道题，产生复习进度和错题本记录。
3. 执行“导出备份”，并将生成的备份文件传输到电脑。
4. 使用电脑的文本编辑器打开该备份文件。

### 验收标准（预期结果）
- [ ] **搜索单词文本**：在文件中搜索刚才背诵的日文单词或中文意思。**预期：找不到**。`wordProgress` 数组下应当纯粹只有数字、布尔值和 `rawId` 等标识符。
- [ ] **搜索敏感设置**：在文件中搜索 `sk-test-123456`（您的测试 Key）。**预期：找不到**。
- [ ] **搜索安全设置**：在文件中搜索 `67`（您设置的每日目标）。**预期：在 `settings` 下面的 `dailyGoal` 能够成功找到它。**

---

## 🧪 测试用例 2：跨设备进度精准挂载与错题本联动

### 操作步骤
1. 在 **设备 B** 上，打开 App（确保词库是最新的，也就是拥有相同的 `rawId` 列表，但由于各种原因，其底层的自增 `wordId` 可能跟设备 A 并不一样）。
2. 在设备 B 上将“大模型 API Key”填入 `sk-b-9999`，每日目标随便写（如 `20`）。
3. 将刚才设备 A 导出的备份文件传给设备 B，并在设备 B 执行“导入”。

### 验收标准（预期结果）
- [ ] **防串线挂载**：进入主页，复习进度（待复习数、已掌握数）应该完美呈现设备 A 的进度。打开背词界面，出现的词精确对应了您在设备 A 上背过的词（这证明了 `rawId` 的映射机制起效了，没有被自增 ID 误导）。
- [ ] **错题本联动**：打开错题本，里面的单词正确无误。
- [ ] **配置合并**：
  - 检查“每日目标”，它变成了 `67`（设备 A 的学习习惯被成功转移）。
  - 检查“大模型 API Key”，它**依然是** `sk-b-9999`（敏感配置没有被覆盖篡改）。

---

## 🧪 测试用例 3：极端异常与丢失容错测试（最高压测试）

### 操作步骤
1. 回到电脑上的文本编辑器，在设备 A 的备份文件 JSON 中，找到任意一个 `WordProgress` 节点。
2. 将该节点的 `"rawId": "xxxx"`，人为篡改成一个世界上不存在的乱码，例如 `"rawId": "GHOST_WORD_999"`。
3. 保存这个篡改过的备份文件，传给设备 B 并执行导入。

### 验收标准（预期结果）
- [ ] **应用稳定性**：导入过程顺利完成，App **绝对不能崩溃（Crash）**。
- [ ] **坚守底线**：打开 App，确认之前被你篡改成了 `GHOST_WORD_999` 的那条进度，**没有**莫名其妙地跑到别的词上（因为找不到对应的 rawId，这条记录会被我们昨天刚写的代码直接丢弃）。这验证了我们的“宁缺毋滥”防卫机制极为牢靠。

---

> 通过以上三个用例的验证，您就可以百分百确信：整个系统的精简、安全过滤与防串线保护完美生效，系统不再含有任何影响长远发展的兼容包袱。
