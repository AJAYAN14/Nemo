# 云端备份与恢复功能测试指南

本文档旨在指导测试“云端备份”及“从云端恢复”功能的业务逻辑与异常处理。请按照以下场景逐一进行验证，确保应用在不同场景下的数据一致性与稳定性。

---

## 一、 测试前置准备

1. **测试设备**：准备至少一台安装了最新测试包的设备（如有条件，可准备两台设备以测试跨设备恢复）。
2. **测试账号**：准备有效的登录账号，确保账号能够正常连接到云服务。
3. **网络环境**：准备可用作切换的 Wi-Fi 与移动网络环境，以及可控制断网的手段（如开启飞行模式）。
4. **抓包/日志工具**：通过 Android Studio Logcat 或抓包工具（如 Charles/Fiddler）以备观察接口返回及状态日志。

---

## 二、 备份到云端 (Backup to Cloud) 测试

### 2.1 正常备份流程 (Happy Path)
* **前置条件**：应用内有一定量的新增用户数据（如词库、设置项、学习记录等），网络正常。
* **操作步骤**：
  1. 触发云端备份操作。
  2. 观察界面 UI 变化（加载动画、进度条或 Toast 提示）。
* **预期结果**：
  1. 提示“备份成功”。
  2. 在“备份历史”（CloudBackupHistoryScreen）中生成了一条最新的备份记录，时间戳和文件大小（如有展示）与当前匹配。
  3. 服务端后台确认成功接收了对应的备份文件或数据。

### 2.2 多次连续备份测试 (覆盖与更新)
* **操作步骤**：
  1. 在本地修改部分数据（修改设置或添加新记录）。
  2. 触发备份并等待其成功。
  3. 在成功后的 60 秒内，再次触发备份。
* **预期结果**：
  1. 界面能有效防抖，提示“备份过于频繁，请稍后再试”。
  2. 60秒内只允许发起一次成功的备份，未满60秒的请求会被直接拦截，不会覆盖云端旧数据。
  3. 超过60秒后再次点击，最新的一次修改能正常触发并成功备份。

### 2.3 网络异常测试
* **操作步骤**：
  1. 在点击“备份”后，**立即断开网络**（开启飞行模式）。
  2. 在无网络环境下点击“备份”。
* **预期结果**：
  1. 断网时操作，应用不能崩溃。
  2. 界面应明确提示“网络异常，备份失败，请检查网络”。
  3. 恢复网络后，再次点击备份可正常成功。

### 2.4 空数据/极限数据备份
* **操作步骤**：
  1. 清除应用所有数据（或使用全新账号登录），本地数据为空。
  2. 点击“备份”。
  3. 造大量数据（如导入几万条记录），然后点击“备份”。
* **预期结果**：
  1. 空数据：允许备份并提示成功（或提示无需备份），云端成功记录空状态。
  2. 大数据：备份耗时变长，但界面有 Loading 防误触，且最终能够备份成功，不会发生 OOM（内存溢出）或接口超时崩溃。

## 三、 从云端恢复 (Restore from Cloud) 测试

> **重点**：此部分重点验证 `RestorePreviewDialog`（恢复预览弹窗）的数据展示准确性，以及恢复后的数据一致性。

### 3.1 正常恢复与预览流程
* **前置条件**：云端已有备份数据，本地数据与云端数据存在差异。
* **操作步骤**：
  1. 触发从云端恢复。
  2. 弹出 `RestorePreviewDialog`（恢复预览弹窗）。
  3. 观察弹窗上展示的“云端数据时间”、“云端数据大小”、“包含的条目数”等概览信息。
  4. 点击“确认恢复”。
* **预期结果**：
  1. 预览弹窗上的数据概览与实际云端保存的数据信息**完全一致**。
  2. 恢复成功后，本地旧数据被成功替换/合并（具体视业务策略，通常为覆盖）。
  3. 重启应用后，恢复的数据依然生效且没有丢失。

### 3.2 跨设备/重装恢复一致性
* **操作步骤**：
  1. 在设备 A 上完成一次备份，包含特定数据。
  2. 在设备 B（或将设备 A 卸载重装后）登录同一账号。
  3. 触发云端恢复。
* **预期结果**：
  1. 能够正常拉取到设备 A 的备份记录。
  2. 恢复完成后，数据状态、UI 展示与之前设备 A 备份时分毫不差。

### 3.3 取消恢复测试
* **操作步骤**：
  1. 触发云端恢复，弹出预览弹窗。
  2. 点击弹窗外的遮罩区域，或点击“取消”按钮。
* **预期结果**：
  1. 弹窗正常关闭。
  2. **本地数据未发生任何改变**。

### 3.4 恢复过程中的网络异常与中断
* **操作步骤**：
  1. 点击“确认恢复”开始下载云端数据时，**立即断开网络**。
  2. 杀掉 App 进程。
* **预期结果**：
  1. 断网应提示“恢复失败，网络连接断开”。
  2. 本地原有数据**不能被破坏**（需要具备原子性或事务回滚能力），即要么恢复完全成功，要么保持恢复前的原样。不能出现数据只恢复了一半导致 App 处于异常状态（如白屏、列表崩溃等）。

## 四、 边缘场景与健壮性测试

### 4.1 账号状态失效
* **操作步骤**：
  1. 在后台主动踢掉该账号（令 Token 过期）。
  2. 回到 App 内尝试点击“备份”或“恢复”。
* **预期结果**：
  1. 接口返回 401（未授权）。
  2. 提示用户“登录已过期，请重新登录”，并将用户引导至登录页面。
  3. 不发生崩溃。

### 4.2 本地高版本向低版本恢复（兼容性）
* *(注：如果云端备份包含了数据库结构或特有的字段)*
* **操作步骤**：
  1. 用高版本的 App 备份了一份含有新特性的数据。
  2. 用旧版本的 App 拉取恢复。
* **预期结果**：
  1. 视业务设计而定：应用应能向下兼容忽略未知字段，或者直接提示“备份数据版本过高，请升级 App 后恢复”。绝对不能直接崩溃。

### 4.3 极限并发点击
* **操作步骤**：
  1. 两根手指同时狂点“备份”和“恢复”。
* **预期结果**：
  1. 界面逻辑互斥，不能同时执行下载和上传。
  2. UI 应有合适的 Loading 遮罩或 Disable 状态阻止并发请求。

---

## 五、 测试验收标准 (Checklist)

- [ ] 备份和恢复的核心流程闭环通过，且数据一致性 100%。
- [ ] 所有的加载等待状态 (Loading) 均有合理的 UI 反馈，防误触机制生效。
- [ ] 中途断网、强杀进程等极端操作**未导致本地原数据库损坏或应用 Crash**。
- [ ] `RestorePreviewDialog` 的弹窗信息展示精确无误，交互符合预期。

祝测试顺利！如发现任何环节与预期不符，请提交对应的 Bug 进行修复。
