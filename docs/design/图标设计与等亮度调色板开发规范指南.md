## 二、核心视觉哲学与硬性设计约束

所有后续改动必须严格遵守以下两条设计铁律：

### 1. 彻底取消外层纯色方块/圆角背景
- **禁止行为**：严禁在图标外围包裹带背景色的卡片框或胶囊底块（例如严禁使用 `Box.background(color.copy(0.15f), RoundedCornerShape(12.dp))`）。
- **规范做法**：图标外层仅保留一个用于保证列表点击区域与间距对齐的纯透明容器（`Modifier.size(42.dp)`），图标本身居中通透排布，消除沉重的“方块贴纸感”。

### 2. Plump Duo 双色线面结合标准
图标必须由 **面（Fill）** 与 **线（Stroke）** 两层立体互补构成：
- **底层浅色面（Soft Fill Layer）**：
  - 提取图形的关键封闭特征面（如云身、表盘内部、人形身体、机器人脸部等）；
  - 填充透明度严格控制在 `alpha = 0.20f ~ 0.26f`（默认推荐 `0.22f`）；
- **表层饱满描边（Bold Stroke Layer）**：
  - 端点必须为圆角（`StrokeCap.Round`），折角必须为圆弧（`StrokeJoin.Round`）；
  - 线宽（Stroke Width）规范为 `2.1f ~ 2.2f` dp；
  - 保持 100% 的饱和主色（`alpha = 1.0f`）；
- **图标尺寸**：在 42dp 的容器内，图标绘制尺寸统一采用 **`28.dp` ~ `30.dp`**（视觉饱满、舒展，杜绝小气干瘪）。

## 三、“感知均匀等亮度调色板”（Isoluminant Palette）规范

### 1. 为什么禁止随意使用普通 RGB 颜色？
人眼视网膜对黄/绿色波长极其敏感，而对深蓝/紫色波长极其迟钝。若直接使用普通 RGB/HSL（如纯蓝 `#0000FF` 对比纯黄 `#FFFF00`），会出现**“黄色极其刺眼晃眼，而蓝色发暗发黑、几乎看不见”**的视觉能量级失衡。

### 2. OKLCH 感知均匀数学模型
本项目的调色板基于 **OKLCH 感知色彩空间** 严格计算：
- **锁定感知亮度（Lightness）**：$L = 62\%$（在浅色和深色模式下均具备极佳对比度）
- **锁定鲜艳度（Chroma）**：$C = 0.165$
- **仅沿 360° 色相环（Hue）均匀取色**

> **统一色彩准则**：所有图标色彩**必须统一通过 `IsoluminantPalette` 获取**（直接引用上方预置常量，或调用下方第 4 节的 `fromOklch` 函数动态生成）。**严禁自行手写未经校准的任意高饱和度 Hex 颜色**。

### 4. 任意色相扩展与模块级色彩语义（拒绝颜色写死与过度重复）

为避免全 App 图标颜色写死或雷同重复，`IsoluminantPalette` 内置了纯数学实现的 **OKLCH 动态色彩算法**：

```kotlin
// 传入 0° ~ 360° 之间任意角度，系统将自动基于 L=62%, C=0.165 计算生成标准的等亮度 Color
val customColor = IsoluminantPalette.fromOklch(hueDegrees = 45f) // 暖金杏色
```

#### 跨界面色彩语义分配标准：
不要在单屏内无序随机使用色彩，建议按**功能模块**建立色彩秩序：
- **设置 / 系统工具**：采用全光谱不同色相区分各配置分支，提升眼动识别效率；
- **词汇本 / 单词卡片**：以暖色系（琥珀金 `70°`、暖橙 `45°`）为主，传递知识与收获感；
- **语法库 / 逻辑树**：以清爽系（翡翠绿 `145°`、青绿 `160°`）为主，传递结构条理；
- **AI 助手 / 智能交互**：以科技感色系（湖光青 `195°`、琉璃青 `175°`）为主；
- **历史记录 / 统计报表**：以沉浸色系（丁香紫 `295°`、蓝紫 `270°`）为主。

## 四、技术实现机制：为什么用纯代码 Kotlin 而不用 XML？

**核心原因**：Jetpack Compose 的官方 `Icon` 控件带有全局单色滤镜（`ColorFilter.tint(color)`）。
- 如果把图标做成 Android XML（`res/drawable/*.xml`），一旦在 Compose 中传入 `tint = color`，Compose 会强制把 XML 里的浅色底面与深色线条**全部刷成一模一样的单色，导致双色质感瞬间消失**。
- 因此，本项目采用 **Kotlin 纯代码 Canvas 双层绘制** 方案：
  1. `PathParser.createPathFromPathData(fillPathData)`：解析底层并绘制半透明色块；
  2. `PathParser.createPathFromPathData(strokePathData)`：解析上层并绘制饱满描边；
  3. 零文件 IO，硬件加速 120fps 渲染，并且支持动态色彩无损注入。

## 五、新增一个图标的标准开发流程（后续 AI 参照操作）

当您需要为新功能添加新图标时，请按以下 5 步执行：

### 步骤 1：在 `E:\GitHub\lucide\icons` 找到目标 SVG
例如需要一个相机图标，在目录中找到 `camera.svg`：
```xml
<svg ... fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round">
  <path d="M14.5 4h-5L7 7H4a2 2 0 0 0-2 2v9a2 2 0 0 0 2 2h16a2 2 0 0 0 2-2V9a2 2 0 0 0-2-2h-3l-2.5-3z"/>
  <circle cx="12" cy="13" r="3"/>
</svg>
```

### 步骤 2：提取描边与闭合填充 Path
- **描边 Path（`strokePathData`）**：合并 SVG 中所有路径与圆弧：
  `"M14.5 4h-5L7 7H4a2 2 0 0 0-2 2v9a2 2 0 0 0 2 2h16a2 2 0 0 0 2-2V9a2 2 0 0 0-2-2h-3l-2.5-3z M15 13a3 3 0 1 1-6 0 3 3 0 0 1 6 0"`
- **填充面 Path（`fillPathData`）**：取外围闭合轮廓（末尾确保有 `Z` 闭合）：
  `"M14.5 4h-5L7 7H4a2 2 0 0 0-2 2v9a2 2 0 0 0 2 2h16a2 2 0 0 0 2-2V9a2 2 0 0 0-2-2h-3l-2.5-3z"`

### 步骤 3：在 `PlumpIcon` 核心枚举中添加项
在 [`core/designsystem/.../icon/PlumpDuoIcon.kt`](file:///e:/Android/Nemo/core/designsystem/src/main/java/com/jian/nemo/core/designsystem/icon/PlumpDuoIcon.kt) 的 `enum class PlumpIcon` 中声明新枚举名：
```kotlin
enum class PlumpIcon {
    ...,
    Camera // 新增相机图标
}
```

### 步骤 4：在对应的业务域分片文件中注册路径
为了防止单文件臃肿，图标路径已按**业务域分片**存放：
- **系统与通用设置**：在 [`PlumpIconsSettings.kt`](file:///e:/Android/Nemo/core/designsystem/src/main/java/com/jian/nemo/core/designsystem/icon/PlumpIconsSettings.kt) 中注册；
- **语音与音频媒体**：在 [`PlumpIconsMedia.kt`](file:///e:/Android/Nemo/core/designsystem/src/main/java/com/jian/nemo/core/designsystem/icon/PlumpIconsMedia.kt) 中注册；
- **用户与账户安全**：在 [`PlumpIconsUser.kt`](file:///e:/Android/Nemo/core/designsystem/src/main/java/com/jian/nemo/core/designsystem/icon/PlumpIconsUser.kt) 中注册；
- **其他新业务模块**（如学习进度、词汇库）：可在同目录下新建对应分片文件（如 `PlumpIconsLearning.kt`）并将其 `Map` 追加进主干的 `PlumpIconRegistry` 聚合表达式中。

注册代码示例：
```kotlin
PlumpIcon.Camera to PlumpIconPathDefinition(
    fillPathData = "M14.5 4h-5L7 7H4a2 2 0 0 0-2 2v9a2 2 0 0 0 2 2h16a2 2 0 0 0 2-2V9a2 2 0 0 0-2-2h-3l-2.5-3z",
    strokePathData = "M14.5 4h-5L7 7H4a2 2 0 0 0-2 2v9a2 2 0 0 0 2 2h16a2 2 0 0 0 2-2V9a2 2 0 0 0-2-2h-3l-2.5-3z M15 13a3 3 0 1 1-6 0 3 3 0 0 1 6 0",
    fillAlpha = 0.22f
),
```

### 步骤 5：在 UI 界面中直接调用

根据实际界面类型，选择以下两种方式之一：

#### 场景 A：在卡片、按钮、顶部栏中使用（原子级图标组件）
适用于任意非设置界面的独立图标展示：
```kotlin
PlumpDuoIcon(
    icon = PlumpIcon.Camera,
    color = IsoluminantPalette.fromOklch(45f), // 既可用常量，也可用 fromOklch 动态色

```

#### 场景 B：在设置页、菜单行中使用（带水波纹点击效果的整行条目）
仅适用于列表行项：
```kotlin
SquircleSettingItem(
    plumpIcon = PlumpIcon.Camera,
    iconColor = IsoluminantPalette.fromOklch(45f),

    subtitle = "使用相机识别单词",
    onClick = { ... }

```

## 六、常见问题与避坑清单

1. **未闭合线条不能作为 `fillPathData`**：
   - 比如箭头线条 `M12 19V5` 是一条直线，若直接作为 `fillPathData` 会在某些图形驱动上造成破面。`fillPathData` 必须是完整的封闭图形（末尾确保带有 `Z`），若图标只有单线（如十字准星），`fillPathData` 请置为 `null`。
2. **SVG 多标签转换规则（`<circle>`、`<line>`、`<rect>`）**：
   - Lucide SVG 中常混用多种基础矢量标签，提取 `strokePathData` 时必须完整转换并拼接到一起，不能只提取 `<path>`：
     - `<circle cx="X" cy="Y" r="R"/>` → `M {X+R} {Y} a {R} {R} 0 1 0 -{2R} 0 a {R} {R} 0 1 0 {2R} 0 Z`
     - `<line x1="A" y1="B" x2="C" y2="D"/>` → `M {A} {B} L {C} {D}`
     - `<rect x="X" y="Y" width="W" height="H" rx="R"/>` → 提取为带圆角的闭合 Path。
3. **跨模块复用的最佳实践（已全面下沉）**：
   - `PlumpDuoIcon.kt` 已全面下沉至 `core:designsystem`（`com.jian.nemo.core.designsystem.icon`）。
   - 全工程各 Feature 模块（`feature:settings`、`feature:user`、`feature:vocabulary` 等）均遵循 Google 单向架构规范单向依赖 `core:designsystem`，同时 `feature:settings` 保留 `typealias` 保证源码级完全兼容。
   - 新增支持了语音参数界面（`Mic`, `Languages`, `Gauge`, `MusicNote`）与账户管理界面（`UserPen`, `Mail`, `KeyRound`, `UserX`）共 8 款官方矢量图标。
4. **深色模式（Dark Mode）透明度适配**：
   - 等亮度调色板 $L=62\%$ 在纯白和纯黑背景上都有极佳对比度；
   - 底层浅色面的默认透明度为 `alpha = 0.22f`。若在 AMOLED 纯黑背景卡片上感觉浅色填充略暗，可微调为 `alpha = 0.26f ~ 0.28f`。
5. **动态色彩的性能与常量缓存**：
   - 在高频滑动列表（如 `LazyColumn`）中使用 `IsoluminantPalette.fromOklch(...)` 时，建议在模块常量文件或单例中定义为固定常量（如 `val WordAmber = IsoluminantPalette.fromOklch(70f)`），避免在 `@Composable` 重组过程中反复计算与分配 `Color` 对象。
6. **严守 Lucide 官方几何比例**：
   - 所有图形严守 24×24 原生网格与 2.1dp 圆角描边质感，杜绝引入外部未经验证的异构图标。
