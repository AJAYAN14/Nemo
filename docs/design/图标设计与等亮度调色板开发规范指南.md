# Streamline Plump Duo 图标设计与开发规范指南

> **文档定位**：本指南专供后续参与 Nemo 项目开发的 AI 助手与工程师阅读。用于在新增、修改、重构全应用各模块（设置、单词库、语法、统计、学习卡片等）的图标时，保持与 Streamline 官方 Plump Duo 规范 100% 对齐的高品质立体视觉与纯正几何网格。

---

## 一、核心目标与正统数据源规范

项目已全面转向 **Streamline 官方原版 Plump Duo 图标体系**，彻底废除过去使用第三方细线条图标（如 Lucide 24×24）手工拼凑双色的过渡做法。后续所有 AI 助手与开发者必须严格遵循以下数据源规范：

| 维度 | 正确规范 | 严格禁止的行为 |
| :--- | :--- | :--- |
| **唯一正统数据源** | **Streamline 官方 `Plump Duo - Free`**（已挂载 Streamline MCP 工具） | 严禁从 Lucide 等第三方库提取 24×24 细线条来手工拼凑；严禁新旧混杂 |
| **几何坐标基准** | **统一 48×48 原生网格（`viewBox="0 0 48 48"`）** | 严禁沿用 24×24 坐标系或引入未经验证的异构网格 |
| **线条与描边质感** | **官方 3px 圆润粗描边（Round Cap & Join）** | 严禁使用 1px~2px 尖锐细线条 |
| **分层结构** | **官方原生分层**：独立闭合底面（Fill） + 独立描边（Stroke） | 严禁通过人工拉伸或随意取封闭面来手工凑合底面 |

> [!CAUTION]
> **旧版图标彻底作废警告（最高执行红线）**：
> 1. **旧版图标全部作废**：项目中现存所有基于 Lucide（24×24）细线条拼凑的旧 `PlumpIconPathDefinition` 路径**全部判定为作废残余**！
> 2. **严禁“照猫画虎”**：后续任何 AI 助手在开发、新增或重构图标时，**严禁参照旧代码的路径格式进行仿写，严禁直接复制或复用旧文件的 PathData**！
> 3. **必须且只能重新提取**：所有图标必须通过已配置的 **Streamline MCP 工具**（或本地官方 48×48 SVG 源文件）重新检索并提取原生双层路径。

## 二、色彩规范：唯一查阅标准（color-palette）

全项目色彩规范已彻底收拢，**完全放弃之前所有的零散色彩推算、旧版等亮度 OKLCH 算法与手工 alpha 透明度猜测**。

所有颜色选择与深浅色模式（Light / Dark Mode）适配，**必须统一且唯一查阅以下本地参考手册**：

📁 **色彩唯一参考手册**：[`docs/design/color-palette/COLORS.md`](file:///E:/Android/Nemo/docs/design/color-palette/COLORS.md)

### 1. 官方原版基准色声明
在 `:core:designsystem` 的 `Color.kt` 中收编官方原版两档基准色：
```kotlin
// Streamline Plump Duo 官方原版标准色
val PlumpDuoStroke = Color(0xFF2859C5)  // 官方原版深蓝描边线 (参考手册系统主色)
val PlumpDuoFill = Color(0xFF8FBFFA)    // 官方原版浅蓝底面 (参考手册次级浅色)
```

### 2. 多模块业务色彩分配
当不同业务模块需要不同色彩主题时，**严禁随意手写未经校准的 Hex 颜色**，必须从 `docs/design/color-palette/COLORS.md` 中选取原生规范色（如 `systemBlue`, `systemGreen`, `systemOrange`, `systemPurple` 等）。

### 3. 中性色铁律（禁止滥用彩色）
原本在设计中不是彩色的中性元素（如列表右侧灰色折角箭头 `ArrowForwardIos`、正文次要说明文字、分隔线、搜索框放大镜、清除 ❌、步进器加减号等），**必须严格查阅手册保持中性文本色（`secondaryLabel` / `onSurfaceVariant`），绝对禁止强行彩色化或 Plump Duo 化！**

## 三、核心视觉哲学与硬性设计约束

### 1. 彻底取消外层纯色方块/圆角背景
- **禁止行为**：严禁在图标外围包裹带背景色的卡片框或胶囊底块（例如严禁使用 `Box.background(color.copy(0.15f), RoundedCornerShape(12.dp))`）。
- **规范做法**：图标外层仅保留一个用于保证列表点击区域与间距对齐的纯透明容器（`Modifier.size(42.dp)`），图标本身居中通透排布，消除沉重的“方块贴纸感”。

### 2. Plump Duo 双色线面结合标准
图标必须由 **底层浅色面（Fill）** 与 **表层饱满描边（Stroke）** 两层构成：
- **底层浅色面（Soft Fill Layer）**：必须直接提取自 Streamline 官方原版 SVG 中的填充图形；
- **表层饱满描边（Bold Stroke Layer）**：端点为圆角（`StrokeCap.Round`），折角为圆弧（`StrokeJoin.Round`），线宽按 48×48 网格基准对应约 **3.0f** 像素粗描边；
- **尺寸规范**：
  - **常规列表项与主功能入口**：统一采用 **`28.dp` ~ `30.dp`**（视觉饱满舒展）；
  - **紧凑型与微小图标场景（禁止放大）**：按钮内嵌小图标、辅助指示箭头、行内提示徽章等原本为 `16.dp` ~ `20.dp` 的场景，必须严格保持 `16.dp` ~ `20.dp`。

### 3. AppBar / 顶部操作栏图标绝对禁止 Plump Duo 化（红线铁律）
- **禁止行为**：严禁在 `TopAppBar`、`CommonHeader`、页面顶部导航栏以及悬浮圆钮（返回键、历史记录、设置齿轮、帮助问号等）中使用 `PlumpDuoIcon`，绝对严禁在此处套用彩色或 Plump 双色！
- **规范做法**：顶部栏的所有操作按钮必须严格保持纯粹单色 Material 矢量图标质感（`Icons.Rounded.*` 或原生 VectorDrawable），图标着色（`tint`）严格遵循主题语义：浅色模式纯黑/文本主色，深色模式纯白。

## 四、技术实现机制：纯 Kotlin Compose 矢量绘制

**为什么不用 XML**：Compose 原生 `Icon` 的 `tint` 滤镜会抹平双色层级；同时 XML 存在资源 IO 开销。

本项目采用 **Kotlin 纯代码 Canvas 双层绘制**（[`PlumpDuoIcon.kt`](file:///E:/Android/Nemo/core/designsystem/src/main/java/com/jian/nemo/core/designsystem/icon/PlumpDuoIcon.kt)）：
1. 底层解析 `fillPathData` 并使用浅色底面；
2. 表层解析 `strokePathData` 并使用 3px 圆润描边；
3. 坐标缩放基准统一为 **`size / 48f`**（与 Streamline 官方 48×48 原生视口严格对齐）；
4. 零文件 IO，硬件加速 120fps 渲染。

## 五、新增与迁移图标的标准开发流程

后续 AI 在开发或重构图标时，必须严格遵照以下五步：

1. **MCP 检索**：调用 Streamline MCP 的 `search_assets`，传入 `setSlug: "plump-duo-free"` 与英文关键词；
2. **提取双层 Path**：调用 `download_asset` 获取 SVG，提取 `<path fill="...">`（底面）和 `<path stroke="...">`（线条）；确保坐标系基于 `viewBox="0 0 48 48"`；
3. **声明枚举**：在 `com.jian.nemo.core.designsystem.icon.PlumpIcon` 中声明语义枚举名；
4. **填入注册表**：在对应的分片注册表（如 `PlumpIconsSettings.kt`）中注册原生路径定义；
5. **登记台账**：**在本文档第六节的《已改造界面台账》中登记落地信息（强制要求）**。

## 七、工程边界条件与防御规范（防踩坑铁律）

后续 AI 助手与开发者在编码落地时，必须严格处理以下 6 大工程边界条件：

### 1. 纯线条图标的“空底面”边界（无 Fill 层处理）
- **现象**：Streamline 官方库中，少数图标（如极简对号、单线条斜箭头、某些特定工具）在原版 SVG 中仅有 `<path stroke="...">`，无闭合填充面（Fill）。
- **执行规范**：
  - 数据模型中 `fillPathData: String? = null` 必须支持可空；
  - 当 `fillPathData == null` 时，**必须直接跳过底层绘制，只执行表层描边**；
  - **严禁强行将未闭合线条（如直线、折线）填入 `fillPathData`**，否则会在底层图形驱动引发破面甚至渲染异常。

### 2. 中空与环形图形的“镂空（EvenOdd）”边界
- **现象**：带有孔洞的图形（如靶心圆环、带锁孔的锁头、字母 O 等），其底层填充面由外圈与内圈复合路径构成。
- **执行规范**：
  - Compose Canvas 在解析并绘制 `fillPath` 时，**填充模式必须显式声明为 `PathFillType.EvenOdd`**；
  - 严禁使用默认的非零缠绕（NonZero），防止内圈孔洞被强制填平变成实心黑块。

### 3. 极小与紧凑尺寸下的“线宽自适应与保护”边界
- **现象**：官方基准为 48×48 网格、3.0f 描边。当处于紧凑型场景（如 16dp ~ 20dp）时：
  - 线宽若固定不缩放，图标内部会被粗线条挤压糊死；
  - 线宽若直接无下限缩小，在小尺寸下会细至不可见。
- **执行规范**：
  - 描边线宽遵循公式：`strokeWidth = 3f * (size / 48f)` 进行等比自适应；
  - 设立**最小保护线宽**（通常不低于 `1.5.dp`），确保大图标饱满圆润、微小图标清晰可辨不糊死。

### 4. 深色模式（Dark Mode）与纯黑背景的对比度边界
- **现象**：官方原版描边色为深蓝（`#2859C5`）。在浅色底上表现极佳，但在 AMOLED 纯黑背景（`#000000` / `#1C1C1E`）下，深蓝会因明度过低而发暗、轮廓失真。
- **执行规范**：
  - 严格遵照 [`docs/design/color-palette/COLORS.md`](file:///E:/Android/Nemo/docs/design/color-palette/COLORS.md) 的深浅模式对照表；
  - 浅色模式下采用官方原版深蓝；深色模式下描边自动适配为参考手册中的**深色模式自发光蓝（`#0A84FF`）**，确保暗黑环境下的可读性。

### 5. 官方 500 款库中无 1:1 同名图标的“语义对齐”边界
- **现象**：特定业务专有概念（如 `GrammarLayers` 语法图层、`IconLab` 图标实验室、`DailyGoalTarget` 学习目标）在官方库中无完全字面同名图标。
- **执行规范**：
  - **严禁擅自造词或拉入外部第三方细线条混杂**；
  - 必须采用**语义对齐**在 Streamline 官方库内匹配（如 `IconLab` 选用官方 `Flask` 烧杯；`GrammarLayers` 选用官方 `Layers` 图层；`DailyGoalTarget` 选用官方 `Target` 靶心）；
  - 若遇多歧义项，必须先列出 2~3 个官方候选方案呈报用户确认，不得私自臆造。

### 6. 严禁改动任何非图标 UI 元素（防连带破坏铁律）
- **执行规范**：
  - 图标重构**严格仅限于替换该图标本身的枚举定义、路径注册与图标组件渲染**；
  - **严禁顺带调整界面的外边距（Margin）、内边距（Padding）、卡片圆角、文本字号或行高**；
  - **严禁修改任何 Switch 开关控件与顶部 AppBar 导航栏组件**。
